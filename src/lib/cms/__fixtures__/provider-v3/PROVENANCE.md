## What it changes for the storefront

- **Revalidation v2** (`revalidation-event-v2.md`): a superset of the v1 body. The endpoint
  keeps accepting v1 bodies unchanged and answers a v2 body with verification `targets`.
- **Preview v1** (`preview-v1.md`): a signed, opaque token resolved server-to-server through
  `POST /api/pages/preview-resolve`; new storefront env var `PAYLOAD_PREVIEW_API_KEY`.
- **Pages v3** (`pages-content.md`): an unsupported or invalid block on an **editorial** page
  is skipped with diagnostics instead of rejecting the whole document. This supersedes the
  `reject-complete-candidate` expectations of the v1 and v2 packs next door for editorial
  pages; a **legal** page (`legalMetadata.documentType: "legal"`) stays fail-closed. Also the
  media focal point and the `maky-cms-revision` marker.

The v1 and v2 packs stay vendored and digest-checked: their fixtures are still valid input
and their REST shape still holds. Only the tolerance rule moved.

## Integrity

`manifest.json` records a SHA-256 for every other file of the pack (`files`);
`provider-v3-conformance.test.ts` recomputes all of them on every run, plus the digest of the
manifest itself. Do not edit a file here — to take a newer pack, replace the files wholesale
and update the table above. `.prettierignore` carries this directory because the digests are
byte-based and the pre-commit formatter rewrites staged files.
